# V77 — consolidation fournisseur par Code

- Identifiant principal : un Code unique de forme `[A-Z][0-9]{4}`. Les espaces et la casse sont normalisés ; les zéros restent significatifs. Un champ historique contenant un seul Code suivi de commentaires est récupéré. Plusieurs codes distincts dans le champ rendent le rattachement ambigu.
- Le nom canonique est le libellé le plus fréquent parmi les enregistrements dédoublonnés portant un Code explicite : une observation par simulation distincte et par ligne PURCHASES distincte. Les variantes d’accents, d’espaces et de ponctuation sont regroupées. Égalité départagée par ordre alphabétique. Le détail des fréquences est accessible dans chaque fiche.
- Sans code valide, rattachement seulement si le nom normalisé correspond à un alias issu d’une ligne avec code explicite et que cet alias ne correspond qu’à un Code. Aucune propagation des alias par les lignes inférées, aucun rapprochement flou, aucun rapprochement sur un champ contenant plusieurs Code.
- La vue indique les rattachements par nom. Les lignes non rattachées sont consultables avec la source, le libellé et la raison. Elles restent conservées dans les imports d’origine.
- Le CA / les achats ne sont plus affichés sur la fiche fournisseur : carte, détails, données du graphique et montants libellés dans les commentaires. Les écarts PURCHASES restent visibles. Les autres pages et les données métier d’origine sont conservées.

Contrôle sur l’extraction consultée pendant la réalisation : 1 238 simulations Planner et 18 221 lignes PURCHASES ; 547 fiches, 16 rattachements par nom unique, 89 lignes non rattachées (87 sans correspondance et deux noms ambigus).

Validation : 287 tests passants, TypeScript et compilation Worker. Rendu serveur vérifié pour l’absence des achats dans la fiche et la conservation des autres notes. Contrôle visuel navigateur non effectué dans cette session.
