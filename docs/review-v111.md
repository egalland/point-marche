# V111 — Édition directe et dispositions de fenêtres

Le Point marché utilise un placement libre unique, y compris pour les anciennes préférences de lecture fluide. Les titres sélectionnent et déplacent les blocs, les bordures les redimensionnent, le clic dans les textes permet de modifier directement. Les bascules de mode et les boutons Modifier/Terminer des en-têtes ont été retirés. Les menus contextuels sont présentés en listes classiques.

Pendant la saisie, le dossier actif utilise la largeur disponible du bloc. Le bloc peut s’agrandir temporairement pour garder son éditeur accessible, sans modifier ses dimensions ou ses coordonnées enregistrées. Le clic extérieur termine la saisie et rétablit la présentation de lecture. Aucune fenêtre ne s’ouvre automatiquement à l’activation de l’éditeur.

La commande Répartir propose un second bloc puis deux colonnes égales, deux lignes égales ou deux tiers/un tiers. Les positions peuvent être inversées ; la pleine largeur et les dimensions précises restent accessibles. Les voisins sont conservés et réorganisés pour éviter le chevauchement. Les dispositions enregistrées restent empilées sur petit écran.

Jira affiche d’abord les volumes et les KPI de résolution. Le bouton Détails des tickets ouvre les filtres, les personnes repliables et les liens des tickets. Le HTML partagé conserve ce fonctionnement ; le mail contient le détail déplié, sans script ni fenêtre.

Validation : tests automatisés et contrôle navigateur sur données fictives. Clic dans le titre sans édition, saisie directe sans fenêtre, restauration de la géométrie après saisie, partage 50/50 et vue par personne contrôlés. Le HTML a été contrôlé avant et après ouverture des détails ; le mail affiche les personnes sans dialogue. Sur 390 pixels, la saisie reste directe et les détails Jira ne débordent pas horizontalement. Le contrôle du mail ne constitue pas un essai dans Outlook.
